# Feature Specification: 日本版・包括的ファイナンシャルプランナー支援アプリ

**Feature Branch**: `001-fp-comprehensive`

**Created**: 2026-05-31

**Status**: Draft

**Input**: User description: "日本のファイナンシャルプランナーの代わりとなる包括的なFPアプリ。ライフプラン・キャッシュフロー表、NISA/iDeCoシミュレーション、住宅ローン計算、教育資金計画、公的年金試算、家計管理を含む。"

## User Scenarios & Testing *(mandatory)*

本アプリは、専門家でない一般家庭の利用者が、自分の家計と将来設計を「見える化」し、
シミュレーションを通じて意思決定を支援するものである。各ユーザーストーリーは独立して
価値を提供し、単独でもMVPとして機能する。

### User Story 1 - ライフプラン・キャッシュフロー表の作成 (Priority: P1)

利用者は、家族構成・年齢・収入・支出・保有資産を入力すると、現在から将来（例: 95歳まで）
にわたる年次キャッシュフロー表と、金融資産残高の推移グラフを得る。これにより「老後資金は
足りるか」「いつ資産が底をつくか」を一目で把握できる。

**Why this priority**: FP相談の中核は生涯キャッシュフロー表の作成である。これ単体で
「将来の家計が破綻しないか」という最重要の問いに答えられ、アプリの存在価値を最も体現する。

**Independent Test**: 家族構成・収入・支出・資産の最小入力だけで、年次の収支・資産残高の
表とグラフが生成され、資産が枯渇する年（あれば）が明示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 35歳・年収500万円・年間支出400万円・貯蓄500万円を入力した状態、**When** キャッシュフロー表を生成、**Then** 各年齢の収入・支出・年間収支・資産残高が表とグラフで表示される
2. **Given** 支出が収入を恒常的に上回る入力、**When** 表を生成、**Then** 資産残高がマイナスに転じる最初の年齢が警告表示される
3. **Given** 退職予定年齢と退職金額を入力、**When** 表を生成、**Then** 退職年に収入構成が給与から年金等へ切り替わり、退職金が資産に反映される
4. **Given** 入力済みのライフプラン、**When** ブラウザを再読み込み、**Then** 入力内容が復元される（ローカル保存）

---

### User Story 2 - NISA / iDeCo / 特定口座の積立シミュレーション (Priority: P2)

利用者は、毎月の積立額・想定利回り・積立期間を入力すると、NISA（非課税）・iDeCo（掛金所得控除＋
運用益非課税）・特定口座（課税）の3パターンの将来資産額と、税制メリットの差額を比較できる。

**Why this priority**: 資産形成の出発点として最も相談が多いテーマ。ライフプランに次いで
利用者の関心が高く、税制優遇の効果を数値で示すことで行動変容を促す。

**Independent Test**: 積立額・利回り・期間を入力するだけで、3口座の最終資産額・運用益・
節税額が算出・比較表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 毎月3万円・年利4%・20年・課税所得330万円超の入力、**When** シミュレーション実行、**Then** NISA/iDeCo/特定口座それぞれの最終評価額と運用益、iDeCoの所得控除による節税累計額が表示される
2. **Given** 特定口座を選択、**When** 計算、**Then** 運用益に対し約20.315%の税が控除された手取り額が表示される
3. **Given** iDeCoを選択、**When** 計算、**Then** 受取時課税は概算であり個別状況で変わる旨の注記が表示される

---

### User Story 3 - 住宅ローンの返済シミュレーション (Priority: P2)

利用者は、借入額・金利・返済期間・返済方式（元利均等／元金均等）を入力すると、毎月返済額・
総返済額・総利息と、返済予定表（償還表）を得る。繰上返済の効果（利息軽減・期間短縮）も試算できる。

**Why this priority**: 住宅購入は人生最大の支出であり、ライフプランへの影響が大きい。
独立して頻繁に使われる計算であり、結果をライフプランに反映できると価値が高い。

**Independent Test**: 借入額・金利・期間を入力するだけで毎月返済額・総返済額・償還表が
生成され、繰上返済入力で総利息が減少することを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 借入3000万円・年利1.0%・35年・元利均等、**When** 計算、**Then** 毎月返済額・総返済額・総利息・年次償還表が表示される
2. **Given** 同条件で10年目に100万円繰上返済（期間短縮型）、**When** 計算、**Then** 短縮される期間と軽減される総利息が表示される
3. **Given** 元金均等を選択、**When** 計算、**Then** 初回返済額が最大で逓減していく返済額推移が表示される

---

### User Story 4 - 教育資金計画 (Priority: P3)

利用者は、子どもの人数・年齢・進路（公立／私立、文系／理系、自宅／下宿等の区分）を選ぶと、
進学時期ごとに必要となる教育費の総額とタイミングを把握し、ライフプランのキャッシュフローに反映できる。

**Why this priority**: 子育て世帯の主要関心事だが、ライフプラン（P1）に統合される支出項目の
一つであり、単独価値はP1〜P2より限定的。

**Independent Test**: 子どもの年齢と進路区分を選ぶだけで、各年に発生する教育費と総額が
年表形式で算出されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 子5歳・全て公立・大学は私立文系（自宅）を選択、**When** 計算、**Then** 幼稚園〜大学卒業までの年次教育費と総額が表示される
2. **Given** 教育費を計算済み、**When** ライフプランに反映、**Then** 該当年の支出にプリセット額が加算される

---

### User Story 5 - 公的年金の概算試算 (Priority: P3)

利用者は、加入区分（会社員／自営業等）・平均年収・加入年数・受給開始年齢を入力すると、
老齢基礎年金＋老齢厚生年金の概算受給額（年額・月額）を把握し、繰下げ・繰上げの増減も確認できる。

**Why this priority**: 老後資金の収入側の根拠として重要だが、概算であり、ライフプラン（P1）の
退職後収入の入力を補助する位置づけ。

**Independent Test**: 加入区分・年収・加入年数・受給開始年齢を入力するだけで、概算の年金額と
繰上げ／繰下げ調整後の額が表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 会社員・平均年収500万円・加入40年・65歳受給、**When** 計算、**Then** 基礎年金＋厚生年金の概算年額・月額が表示される
2. **Given** 受給開始を70歳に変更、**When** 計算、**Then** 繰下げによる増額（最大+42%相当）が反映される
3. **Given** いずれの試算、**When** 結果表示、**Then** 「概算であり日本年金機構の正式試算ではない」旨が明示される

---

### User Story 6 - 家計管理（収支の把握） (Priority: P3)

利用者は、月次の収入・支出をカテゴリ別に記録し、月間収支・カテゴリ別構成・貯蓄率を把握できる。
記録した平均支出は、ライフプランの支出前提として取り込める。

**Why this priority**: 入力データの精度を高めライフプランの前提を裏付けるが、本アプリの
中核（将来設計）に対しては補助的。

**Independent Test**: 月次の収入・支出を入力するだけで、月間収支・貯蓄率・カテゴリ別内訳が
集計表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 当月の収入と複数カテゴリの支出を入力、**When** 集計、**Then** 月間収支・貯蓄率・カテゴリ別構成比が表示される
2. **Given** 数か月分の記録、**When** 平均を算出、**Then** ライフプランの年間支出前提に反映できる

---

### Edge Cases

- 収入0・支出0など極端な入力時に、ゼロ除算やNaNを起こさず妥当な結果（または入力促し）を返すか
- 想定利回りに負の値（マイナス運用）を入れた場合、損失として正しく逓減するか
- 返済期間より短い時点での繰上返済額が残債を上回る場合、完済として扱い過剰計算しないか
- 受給開始年齢を制度上の範囲外（例: 59歳や76歳）にした場合、範囲内に制限または警告するか
- 資産が生涯を通じて一度も枯渇しない場合に、誤った枯渇警告を出さないか
- localStorageが利用不可（プライベートモード等）の場合に、保存不可を通知し計算自体は継続できるか
- 100歳超の長寿前提でも表・グラフが破綻せず描画されるか

## Requirements *(mandatory)*

### Functional Requirements

**共通・基盤**

- **FR-001**: システムは利用者の入力データ（家族構成・収入・支出・資産・各種前提）を利用者端末内にのみ保存し、外部サーバーへ送信してはならない（MUST NOT）。
- **FR-002**: システムは起動時および各シミュレーション結果画面に「本アプリの出力は一般的な情報提供・概算であり、専門的助言ではない」旨の免責を表示しなければならない（MUST）。
- **FR-003**: システムは特定の金融商品の購入を推奨・勧誘してはならない（MUST NOT）。
- **FR-004**: システムは税率・料率・控除額など改定されうる数値について、適用年度と概算である旨を結果またはヘルプ上で明示しなければならない（MUST）。
- **FR-005**: 利用者は入力したデータを編集・削除でき、全データの一括削除（リセット）が可能でなければならない（MUST）。

**ライフプラン / キャッシュフロー（US1）**

- **FR-010**: 利用者は本人（および配偶者）の現在年齢・収入・退職予定年齢・退職金、子どもの人数と年齢を入力できなければならない（MUST）。
- **FR-011**: システムは現在から指定終了年齢（既定95歳）までの年次キャッシュフロー表（収入・支出・年間収支・金融資産残高）を生成しなければならない（MUST）。
- **FR-012**: システムは金融資産残高の推移を時系列グラフで表示しなければならない（MUST）。
- **FR-013**: システムは資産残高が初めて負に転じる年齢を検出し、警告として明示しなければならない（MUST）。
- **FR-014**: システムは収入・支出に対する年次の変動率（昇給率・インフレ率等の前提）を任意で設定でき、未設定時は妥当な既定値（例: 0%）で計算しなければならない（MUST）。

**積立シミュレーション（US2）**

- **FR-020**: 利用者は毎月積立額・想定年利・積立年数を入力できなければならない（MUST）。
- **FR-021**: システムは積立の将来評価額を複利で算出しなければならない（MUST）。
- **FR-022**: システムはNISA（非課税）・特定口座（運用益に約20.315%課税）・iDeCo（掛金所得控除＋運用益非課税）の3区分の結果を比較表示しなければならない（MUST）。
- **FR-023**: システムはiDeCoの掛金所得控除による概算節税額を、利用者が選択した課税所得帯に基づき算出しなければならない（MUST）。

**住宅ローン（US3）**

- **FR-030**: 利用者は借入額・年利・返済期間・返済方式（元利均等／元金均等）を入力できなければならない（MUST）。
- **FR-031**: システムは毎月返済額・総返済額・総利息および年次（または月次）償還表を生成しなければならない（MUST）。
- **FR-032**: 利用者は任意時点の繰上返済額と方式（期間短縮／返済額軽減）を入力でき、システムは軽減される利息および短縮期間（または軽減後返済額）を算出しなければならない（MUST）。

**教育資金（US4）**

- **FR-040**: 利用者は子どもごとに年齢と進路区分（幼稚園〜大学の公私・文理・通学形態）を選択できなければならない（MUST）。
- **FR-041**: システムは進路区分に対応する標準的教育費（出典付き目安）を用い、各年の教育費と総額を算出しなければならない（MUST）。
- **FR-042**: システムは算出した教育費をライフプランの支出に取り込めなければならない（SHOULD）。

**公的年金（US5）**

- **FR-050**: 利用者は加入区分・平均年収・加入年数・受給開始年齢を入力できなければならない（MUST）。
- **FR-051**: システムは老齢基礎年金と老齢厚生年金の概算受給額（年額・月額）を算出しなければならない（MUST）。
- **FR-052**: システムは繰上げ受給（減額）・繰下げ受給（増額）を制度上の範囲（60〜75歳）で反映しなければならない（MUST）。

**家計管理（US6）**

- **FR-060**: 利用者は月次の収入・支出をカテゴリ別に記録できなければならない（MUST）。
- **FR-061**: システムは月間収支・貯蓄率・カテゴリ別構成比を集計表示しなければならない（MUST）。

### Key Entities *(include if feature involves data)*

- **世帯（Household）**: 利用者本人・配偶者・子どもの集合。各メンバーの生年・年齢を持つ。
- **収入（Income）**: 給与・事業・年金・その他。金額、発生開始/終了年齢、変動率を属性に持つ。
- **支出（Expense）**: 生活費・住居費・教育費・保険等のカテゴリ別年間/月間額。変動率を持つ。
- **資産（Asset）**: 現預金・投資・退職金等の残高。運用利回りを属性に持つ。
- **ライフイベント（LifeEvent）**: 特定年齢で発生する一時的な収入/支出（住宅購入、車購入、退職金等）。
- **積立プラン（InvestmentPlan）**: 月額・利回り・期間・口座種別（NISA/iDeCo/特定）。
- **ローン（Loan）**: 借入額・金利・期間・返済方式・繰上返済イベント。
- **年金前提（PensionProfile）**: 加入区分・平均年収・加入年数・受給開始年齢。
- **キャッシュフロー結果（CashflowProjection）**: 年齢ごとの収入・支出・収支・資産残高の系列（計算結果、永続化任意）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めての利用者が、サンプル入力を用いて最初のキャッシュフロー表とグラフを得るまでに5分以内で到達できる。
- **SC-002**: ライフプランの主要入力（家族・収入・支出・資産）を行うと、資産が枯渇する年齢の有無が必ず明示される（該当する全シナリオで判定漏れ0件）。
- **SC-003**: 積立・住宅ローン・年金の各計算結果が、信頼できる出典に基づく手計算の期待値と一致する（単体テストで全件合格、相対誤差は丸め方針の範囲内）。
- **SC-004**: すべてのシミュレーション結果画面に免責表示が存在する（全画面で表示率100%）。
- **SC-005**: 個人金融データの外部送信が発生しない（ネットワーク監査で送信0件）。
- **SC-006**: ブラウザ再読み込み後も入力データが復元される（保存・復元の成功率100%、localStorage利用可能時）。
- **SC-007**: 主要操作（入力→計算→結果閲覧）がエラーや行き止まりなく完了できる（主要フロー完了率の目標90%以上）。

## Assumptions

- 利用者は日本在住・日本円ベースの家計を前提とし、UIは日本語を既定とする。
- 単一利用者（単一世帯）の利用を前提とし、マルチユーザー/アカウント管理はv1のスコープ外とする。
- 個人金融データはブラウザのlocalStorageに保存し、外部DB・サーバー・認証はv1では用いない。
- 税制・料率・教育費・年金算定式は「概算用の代表値・簡略式」を用い、正式な個別試算・申告には用いない（出典と適用年度を明記）。
- 想定利回り・インフレ率・昇給率は利用者が前提として入力するものであり、将来を保証しない。
- 金融機関連携（口座自動取得）やレシート読取等の外部連携はv1のスコープ外とする。
- 対応環境はモダンな主要ブラウザ（デスクトップ）を前提とし、モバイル最適化はベストエフォートとする。
